# What this verifies

HC88 inverted the HARD-FAIL gate in `_reconcileBeforeDequeue`'s caller
(app.js:10520-10553) so that HARD-FAIL fires *only* when SMALL is
genuinely missing from the server. The previous gate condition
(`else if (smallAssembling > 0 && smallMissing === 0)` for WAIT) fell
through to HARD-FAIL when only `softAssembling` was non-empty —
triggering false re-upload loops while MEDIUM/ORIGINAL were still
mid-assembly server-side.

The probe drives all 8 combinations of (smallMissing, smallAssembling,
softAssembling) directly against the inverted branch logic and asserts
the correct branch fires. Plus a bound test: 13 consecutive WAIT
calls should promote the 13th tick to WAIT-EXHAUSTED (3-min cap).

# Expected behaviour matrix

  sM = smallMissing count       (genuine missing — must HARD-FAIL)
  sA = smallAssembling count    (server has SMALL, still stitching)
  soA = softAssembling count    (server has MEDIUM/ORIGINAL, stitching)

  All-zero  → OK + dequeue
  Any soft-only or assembling → WAIT-ASSEMBLY (defer 15s, no re-upload)
  Any smallMissing > 0       → HARD-FAIL + re-queue
